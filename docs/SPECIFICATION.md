# Smart Virtual Assistant

> [!IMPORTANT]
> **Evidence Required:** Design, code, and evaluation

## Core Objectives
Design a computational process (understand → decompose → represent → decide → execute → verify → improve) to solve an ambiguous human need. **The focus is on system design, routing, validation, and fallback mechanisms, rather than simply routing all inputs to a single LLM**.

## Minimum System Requirements
| ID | Requirement | Description / Evidence |
|---|---|---|
| **R1** | Problem boundary | Specific target user, pain point, 8-12 representative use cases, explicit non-goals, measurable success criteria. |
| **R2** | Deterministic capability | At least one transparent and testable rule/algorithm/calculation. |
| **R3** | Data / retrieval capability | At least one structured/unstructured information source with retrieval logic. |
| **R4** | AI-enabled capability | At least one AI/ML/LLM capability technically justified by the problem. |
| **R5** | Routing/orchestration | Explicit mechanism deciding which capability handles a request (includes fallback). |
| **R6** | End-to-end interface | User-facing interface or API flow connected to backend logic. |
| **R7** | Reliability & safeguards | Input validation, error handling, timeout behavior, privacy rules, prompt-injection defenses. |
| **R8** | Evaluation | Repeatable benchmark/test set, metrics, error taxonomy, and ≥1 improvement cycle. |

## Submission Package Deliverables
1.  **Engineering Report:** 12-18 pages covering problem framing, architecture, risks, evaluation, limitations.
2.  **Source Repository / Demo:** Code, dependency files, reproducible setup, working demo (no real credentials).
3.  **Architecture & Design Pack:** Context/component/flow diagrams, schemas, pseudocode.
4.  **Evaluation Pack:** Benchmarks, labels, evaluation scripts, error taxonomy, before/after evidence.
5.  **Failure & Risk Pack:** Threat analysis, safeguards, red-team cases.
6.  **Presentation & Final Demo:** Technical story, demo, and lessons learned.
7.  **Team Logbook:** Weekly task allocation, meeting notes, contribution summary.

## Evaluation Rubric
| Criterion | Weight | Focus Areas |
|---|---|---|
| Problem framing & CT reasoning | 15% | Clear boundary, success metrics, strong decomposition/abstraction. |
| System architecture & orchestration | 15% | Coherent components, data flow, routing, fallback. |
| Data/retrieval layer | 10% | Appropriate sources, provenance, retrieval logic. |
| Algorithm & technology selection | 10% | Justified choices (logic, AI, tools), avoiding unnecessary complexity. |
| MVP & integration | 20% | End-to-end reliability, understandable and reproducible code. |
| Reliability, security & responsible AI | 10% | Failure model, privacy, safeguards, red-teaming. |
| Testing & evaluation | 10% | Balanced benchmarks, meaningful metrics, regression testing. |
| Report, demo & presentation | 10% | Professional communication, evidence-centered demo. |
